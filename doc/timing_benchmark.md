# 화면 인식·계산 평균 소요시간 측정

- 측정일: 2026-11-13
- 측정 스크립트: [`poker/tools/timing_benchmark.py`](../poker/tools/timing_benchmark.py)
- 단위: 별도 표기가 없으면 ms

## 요약

- **판단 1회(화면 인식 + 계산)에 평균 약 0.75초** 걸렸다. 실제 테이블 스크린샷 2장으로 측정했고, 각각 30회씩 3번 실행했다.
  - **화면 인식**: 평균 466 ms(PokerStars) / 497 ms(PartyPoker). 이 중 약 103 ms는 코드에 들어 있는 고정 대기(`time.sleep(0.1)`)다. 이를 빼면 실제 처리 시간은 363 / 394 ms다.
  - **계산**(몬테카를로 + 의사결정): 평균 277 ms / 254 ms.
- 계산 시간은 게임 단계와 상대 수에 따라 **0.17~0.80초**로 달라진다. 플랍에서 상대가 3명 이상(코드가 가정하는 플레이어 4명)일 때 가장 길다(평균 804 ms, p95 1.0초).
- 몬테카를로가 시간 제한(`config.ini`의 `montecarlo_timeout`, 8초)에 걸린 경우는 없었다.
- 전략 서버 HTTP 요청, 실제 화면 캡처, 마우스 동작은 측정에 포함되지 않았다. 자세한 내용은 [측정에 포함되지 않은 시간](#측정에-포함되지-않은-시간)에 정리했다.

## 측정 환경

| 항목 | 값 |
|---|---|
| CPU | Intel Xeon 2.10GHz, 4 vCPU (클라우드 컨테이너, Linux) |
| Python | 3.11.18 (배포 빌드 워크플로와 같은 버전) |
| 주요 패키지 | numpy 1.26.4, pandas 2.0.3, OpenCV 4.11.0, Tesseract 5.5.4(tesserocr), lmfit 1.3.3 |
| 화면 크기 | 1920×1080 |
| 반복 | 시나리오마다 30회 측정(워밍업 3회 제외) × 3번 실행 |

표의 평균과 중앙값은 3번 실행한 값의 평균이고, p95는 3번 중 가장 큰 값이다. 판단 1회 합계의 실행별 평균은 PokerStars가 732~750 ms, PartyPoker가 706~818 ms였다(PartyPoker는 첫 실행의 몬테카를로가 느렸다).
PC 사양에 따라 결과가 달라지므로, 실제로 사용할 PC에서 같은 스크립트를 실행해 보는 것이 좋다([재현 방법](#재현-방법) 참고).

## 측정 방법

- 원래 봇은 테이블 템플릿(카드·버튼 이미지와 좌표)과 전략을 원격 서버(`dickreuter.com:7778`)에서 내려받는다. 측정 시점에는 이 서버가 TLS 연결을 끊어 사용할 수 없었다.
- 그래서 저장소의 테스트 스크린샷 2장으로 테이블 매핑을 직접 만들었다.
  - `poker/tests/screenshots/ps473830744_Flop_1.png`: PokerStars 6인 테이블, 턴(보드 4장)
  - `poker/tests/screenshots/53269218_PreFlop_0.png`: PartyPoker 6인 테이블, 프리플랍
  - 화면에 보이는 카드, 버튼, 딜러 버튼, 상대 카드 뒷면은 스크린샷에서 잘라 템플릿으로 썼다. 화면에 없는 카드(46~50장)와 체크·벳·올인 버튼 등은 같은 크기의 무작위 이미지로 채웠다. 템플릿 검색에 걸리는 시간은 이미지 내용과 상관없이 크기에 따라 정해지므로 검색 비용은 그대로 측정된다.
  - 스크린샷을 1920×1080 바탕화면 이미지의 왼쪽 위에 붙여 캡처 화면으로 사용했다. 이후 [캡처 영역 선택 기능](capture_area.md)을 추가하면서 스크립트는 테이블을 (200,100)에 두도록 바뀌었다. 결과 1~3은 바뀌기 전의 측정값이다.
- **화면 인식**은 `main.py`의 `ready` 체인과 같은 함수를 같은 순서로 호출했다. 판단 1회당 템플릿 검색은 118~122회, OCR은 6회였다.
- 인식 결과는 두 테이블 모두 기대값과 일치했다. 확인한 값은 내 카드, 보드, 딜러 위치, 참여 플레이어, 내 보유금, 팟, 콜 금액, 레이즈 금액이고, OCR 기대값은 기존 테스트 `test_ocr_ps1`, `test_ocr_pp1`의 값과 같다.
- **계산**은 `run_montecarlo_wrapper`와 `Decision`/`make_decision`을 그대로 호출했다. 전략값은 스크립트에 들어 있는 로컬 전략(`BENCHMARK_STRATEGY`)을 썼다.
  - 몬테카를로 반복 횟수는 전략값과 상관없이 단계별로 정해져 있다(프리플랍 3000, 플랍 5000, 턴 4000, 리버 3000).
  - 전략의 상대 레인지 값은 표본을 다시 뽑는 횟수에만 영향을 준다.
- GUI 신호, 마우스, 게임 로거(DB)는 스텁으로 바꿨다.

## 결과 3: 게임 단계·상대 수별 계산 시간

PokerStars 인식 결과를 복사한 뒤 보드 카드와 참여 상대 수만 바꿔서 계산 시간만 측정했다. 괄호 안은 p95다.
6인 테이블에서 코드가 가정하는 플레이어 수는 최대 4명(`total_players - 2`)이고, 프리플랍에서는 상대 수와 상관없이 항상 2명이다.

| 단계 | 몬테카를로 반복 | 상대 1명<br>(가정 2명) | 상대 2명<br>(가정 3명) | 상대 4명<br>(가정 4명) |
|---|---:|---:|---:|---:|
| 프리플랍 | 3000 | 218 (346) | 상대 1명과 같음 | 상대 1명과 같음 |
| 플랍 | 5000 | 355 (472) | 609 (808) | 804 (1003) |
| 턴 | 4000 | 262 (381) | 463 (639) | 649 (863) |
| 리버 | 3000 | 167 (237) | 311 (457) | 413 (539) |

의사결정 자체는 5~20 ms이고, 계산 시간의 대부분은 몬테카를로다. 몬테카를로는 순수 Python 루프라서 반복 횟수와 가정 플레이어 수가 늘어날수록 대체로 비례해서 길어진다.

## 측정에 포함되지 않은 시간

- **전략 서버 요청**: `ready` 체인의 `strategy.read_strategy()`가 매 사이클마다 서버로 `get_strategy` HTTP 요청(`requests.post`, 연결 재사용 없음)을 보낸다. 서버를 쓸 수 없어 측정하지 못했다. 네트워크 왕복 시간과 TLS 연결 시간이 그대로 화면 인식 시간에 더해진다.
- **화면 캡처** `ImageGrab.grab()`: 참고로 이 환경의 가상 X 디스플레이(Xvfb, 1920×1080)에서는 평균 34 ms였다. Windows에서는 따로 확인해야 한다.
- 마우스 이동·클릭과 그 사이의 무작위 대기, GUI 갱신, 로그 기록(별도 스레드), 판단 후 `mongo.increment_plays` 서버 요청.
- 신경망 카드 인식(`use_neural_network`)을 쓰는 테이블. TensorFlow 경로는 측정하지 않았다.
- 내 차례가 올 때까지 `ready` 루프가 반복되는 시간. 위 수치는 성공한 마지막 1회만 기준으로 했다.

## 측정 중 확인한 점

1. **lmfit 1.3.4에서는 의사결정 단계가 실패한다.**
   - `poker/decisionmaker/curvefitting.py`의 `fcn2min`이 리스트 `xf`에 실수를 더하는데(`x + adj2`), lmfit 1.3.3까지는 동작한다.
   - 1.3.4에서는 `TypeError: can only concatenate list (not "float") to list`가 난다.
   - requirements 파일에 lmfit 버전이 고정되어 있지 않아 새로 설치하면 이 문제가 생긴다. 이번 측정에는 1.3.3을 썼다.
2. **테이블이 화면 왼쪽 위 (0,0)에 있지 않으면 새 핸드의 첫 판단이 늦어진다.**
   - 새 핸드를 감지하면 `get_new_hand`가 화면을 다시 캡처하는데, 캡처한 화면을 다시 잘라내지 않는다. 그래서 이후 단계는 테이블 기준 좌표로 전체 화면을 읽게 된다.
   - 테이블이 (0,0)에 있지 않으면 새 핸드 첫 사이클의 인식이 실패하고 `ready` 루프를 한 번 더 돈다. 테이블을 (200,100)에 두었을 때 `check_for_button`에서 멈추는 것을 확인했다.
   - 이 경우 새 핸드의 첫 판단은 인식 1회분(약 0.4~0.5초) 이상 늦어진다.
   - 결과 1~3은 테이블을 (0,0)에 두고 측정했다.
   - 이 문제는 [캡처 영역 선택 기능](capture_area.md)을 추가하면서 고쳤다. 새 핸드에서 다시 찍은 화면도 이미 찾은 테이블 위치로 잘라낸다.

## 재현 방법

저장소 루트에서 실행한다.

```bash
pip install -r requirements_win.txt
```

```bash
pip install "lmfit==1.3.3"
```

```bash
python -m poker.tools.timing_benchmark --repeat 30 --warmup 3 --json timing.json
```

- `--repeat`: 시나리오마다 측정할 횟수(기본 20)
- `--warmup`: 측정에서 제외할 처음 실행 횟수(기본 2)
- `--json`: 단계별 평균, 중앙값, p95 등 결과 전체를 JSON으로 저장
- `--capture`: `full_screen`(기본, 바탕화면 전체 캡처) 또는 `window`(테이블 창만 캡처)
- `--no-stages`: 게임 단계·상대 수별 계산 측정(결과 3)을 건너뜀
- `--verbose`: 봇의 로그 출력 표시
