# pokerlab

자체 텍사스 홀덤 시뮬레이터, 승률(에퀴티) 계산기, 공개 핸드 히스토리로 학습한 상대 레인지 모델, 그리고 봇 자가대전으로 매일 학습하는 파이프라인입니다. 학습·복기·자체 게임용이며, 같은 저장소의 `poker/`(실제 포커 사이트 화면을 읽는 봇)와는 완전히 독립적입니다. 화면 인식·마우스 제어·외부 서버가 필요 없고, 의존성은 NumPy와 pandas뿐입니다.

| 모듈 | 역할 |
|---|---|
| `cards.py` | 카드 표기(`As`, `Td`, `A♠`) 파싱, 169개 스타팅 핸드 분류 |
| `evaluator.py` | 5~7장 족보 평가기 (단건용 순수 Python + 대량용 NumPy 벡터화) |
| `equity.py` | 승률 계산: 전수 계산 또는 몬테카를로, 가중치 레인지, 전원 매치업, 다음 카드별 승률 |
| `preflop.py` | 프리플랍 승률 테이블(169핸드 × 상대 1~9명), 레인지 표기(`TT+, AQs+, 15%`) 파서 |
| `inference.py` | 상대의 액션 이력으로 레인지를 추정하는 모델: 학습(숨은 카드는 EM), 추정, 정확도 평가 |
| `phh.py` | 공개 핸드 히스토리(PHH 형식) 읽기 |
| `advisor.py` | 한 상황을 숫자·한국어 해석·JSON으로 정리 |
| `web.py`, `static/` | 카드를 클릭해서 쓰는 로컬 웹 화면 |
| `engine.py` | 노리밋 홀덤 한 판 진행 (블라인드, 최소 레이즈, 올인, 사이드팟, 스플릿) |
| `bots.py` | 봇: `station`, `random`, `maniac`, 에퀴티 기반 `nit`/`tag`/`lag`/`tag_range`/`tag_model`, 학습된 `champion`, 실전 데이터의 습관대로 치는 `human`/`pro` |
| `selfplay.py` | 봇끼리 자동 대전시키고 모든 핸드를 SQLite에 누적 (멀티프로세스, 중단 후 이어하기) |
| `report.py` | 누적 DB에서 봇별 bb/100, 포지션·인원·핸드별 통계 |
| `daily.py` | 하루 한 번 도는 학습 사이클: 대전 → 학습 → 검증 → 기록 |

### 웹 화면

```bash
python -m pokerlab serve
```

브라우저에서 `http://127.0.0.1:8765` 를 엽니다. 카드를 클릭해 내 핸드와 보드를 채우면 승률, 승/무/패 비율, 최종 족보 확률, 다음 카드별 승률, 상대 수별 승률이 바로 계산됩니다. 상대를 추가해 액션(예: 오픈 레이즈 → 플랍 벳)을 넣으면 추정 레인지가 13×13 표로 표시되고 승률이 그 레인지 기준으로 바뀝니다. 테이블 크기와 나·상대의 포지션을 고르면 추정에 반영되고, 액션을 어떤 플레이어들의 습관으로 해석할지(실전 온라인, 프로, 봇)도 고를 수 있습니다.

### 명령줄

```bash
python -m pokerlab equity AsKs --board "Qs Js 2d" --players 2 --position bb --villain "btn: open/bet" --pot 100 --to-call 50
```

```
[플랍] 내 핸드 As Ks (AKs) | 보드 Qs Js 2d | 2명 (상대 1명, 레인지 지정)
승률(에퀴티) 70.76%  = 승 69.72% + 무 2.09% 분배 / 패 28.19%   (전수 계산, 오차 없음)
판정: 강함  (인원 기준 평균 승률 50.0%의 1.42배)
상대1 레인지 (btn: open/bet): 전체 핸드의 약 45% 폭 | 비중 상위 ATo 2%, AQo 2%, QTo 2%, Q9o 2%, AJo 2%, KTo 2%
현재 족보: 하이카드  | 지금 당장 쇼다운이면 랜덤 핸드 1개 상대로 앞섬 59.2% / 동률 0.8% / 뒤짐 40.0%
리버까지 갔을 때 내 최종 족보: 플러시 31.1%, 원페어 28.8%, 하이카드 18.0%, 스트레이트 9.9%, ...
다음 카드별 승률: 스트레이트 플러시 1장 → 100%, 플러시 8장 → 98%, 스트레이트 3장 → 96%, 원페어 14장 → 70%, 하이카드 21장 → 56%
  승률이 10%p 이상 오르는 카드 18장, 10%p 이상 떨어지는 카드 29장 (전체 47장)
팟 오즈: 팟 100에 50 콜 -> 필요 승률 33.3%, 내 승률 70.8% -> 콜 기대값 +56.1 (수익 콜)
```

| 옵션 | 뜻 |
|---|---|
| `--players N` | 지금 판에 남은 인원, 나 포함 (2~10) |
| `--table N` | 테이블에 앉은 인원. 생략하면 6인(남은 인원이 6명을 넘으면 9인)으로 가정 |
| `--range R` | 상대 한 명의 레인지를 직접 지정. `TT+,AQs+`, `15%`, 카드 지정 `QhQd`. 여러 번 가능 |
| `--villain LINE` | 상대 한 명의 액션. 스트리트는 `/`로 구분하며 레인지를 모델이 추정. 좌석을 알면 `btn: open/bet`처럼 앞에 붙임. 여러 번 가능 |
| `--position SEAT` | 내 좌석 (`ep mp co btn sb bb`). 상대 좌석과 함께 주면 플랍 이후 누가 나중에 행동하는지까지 반영 |
| `--model NAME` | 액션을 해석할 모델: `online`(기본), `pro`, `selfplay` 또는 모델 파일. `--profile`로 그 안의 유형 선택 |
| `--pot`, `--to-call`, `--bet` | 팟 오즈, 콜 기대값, 베팅 손익분기 계산 |
| `--precision 0.05` | 95% 신뢰구간이 ±0.05%p가 될 때까지 시뮬레이션 |
| `--json` | 숫자를 JSON으로 출력 |

액션 단어는 프리플랍 `limp open call 3bet call3bet 4bet check`, 플랍 이후 `check bet call raise callraise reraise`입니다. 좌석은 `ep`(얼리), `mp`(미들), `co`(컷오프), `btn`(버튼), `sb`, `bb`이고 `utg`, `hj`도 받습니다. 액션 한 줄에는 그때 누가 폴드해 있었는지가 없으므로, 프리플랍은 그 좌석 앞이 모두 폴드한 상황으로 가정합니다.

모든 플레이어의 승률을 한 번에 보려면 `matchup`을 씁니다. 핸드가 전부 정해져 있으면 남은 보드를 전수 계산합니다.

```bash
python -m pokerlab matchup AhKd QsQc
```

```
보드 없음 | 전수 계산 (1,712,304가지)
  AhKd             승률  42.84%  (승 42.66% / 무 0.34%)
  QsQc             승률  57.16%  (승 56.99% / 무 0.34%)
```

### Python

```python
from pokerlab.equity import equity, matchup, next_card
from pokerlab.inference import range_from_line
from pokerlab.preflop import parse_range

equity("AsKs", "Qs Js 2d", n_opponents=3)                        # .equity .win .tie .ci95 .hand_dist
equity("AsKs", n_opponents=5, precision=0.001)                   # ±0.1%p가 될 때까지
equity("AhKd", ranges=[parse_range("QQ+")])                      # 상대 레인지 지정
equity("AsKs", "Qs Js 2d", ranges=[range_from_line("open/bet", "AsKs", "Qs Js 2d")])
matchup(["AsKs", parse_range("TT+"), None], "Qs Js 2d")          # 핸드, 레인지, 랜덤 핸드
next_card("AsKs", "Qs Js 2d")                                    # {카드: 그 카드가 나온 뒤 승률}
```

## 매일 학습

```bash
python -m pokerlab daily
```

한 사이클이 하는 일은 다음과 같습니다. 두 가지를 학습하며, 둘 다 새 핸드에서 검증을 통과해야 반영됩니다.

1. **대전**: 현재 챔피언, 파라미터를 조금 바꾼 도전자, 고정 상대 4명이 6인 테이블에서 대전합니다. 고정 상대는 실전 온라인 데이터의 습관대로 치는 `human` 2명과 `nit`, `tag_range`이며 `--opponents`로 바꿀 수 있습니다. 도전자마다 6만 핸드, 기본 3명입니다.
2. **베팅 전략 학습**: 같은 핸드들에서 도전자와 챔피언의 손익 차이를 구해, 95% 신뢰구간 하한이 0보다 크면 도전자가 챔피언이 됩니다.
3. **레인지 모델 학습**: 그날 핸드의 액션 통계를 기존 통계에 더합니다(기존 값은 0.9배로 감쇠). 학습에 쓰지 않은 핸드 20%에서 승률 추정 오차를 재고, 이전 모델보다 2% 넘게 커지지 않았을 때만 교체합니다.
4. **기록**: `data/action_model.json`, `data/champion.json`, `data/history.jsonl`에 저장합니다.

```bash
python -m pokerlab history
```

기본 설정 한 사이클은 18만 핸드이고 4 vCPU에서 약 7분 걸립니다. 지금까지 세 사이클에서 도전자 8명 모두 챔피언과 유의한 차이가 없어(−32 ~ +10 bb/100, 신뢰구간 ±11~23) 챔피언이 유지됐고, 레인지 모델은 세 번 모두 반영됐습니다. `human` 봇을 넣은 세 번째 사이클의 순위는 챔피언 +30, 도전자 +26, `tag_range` +3, `human` −9, `nit` −40 bb/100으로, 이전 상대 풀(챔피언 +100)보다 훨씬 팽팽합니다.

`--cycles 0`이면 중단할 때까지 사이클을 반복합니다. 하루 한 번만 돌리려면 cron에 등록합니다.

```bash
(crontab -l; echo "37 4 * * * cd $PWD && python -m pokerlab daily >> pokerlab-daily.log 2>&1") | crontab -
```

## 검증 결과

- **족보 평가기**: 5장 조합 2,598,960개와 7장 조합 133,784,560개를 전수 평가한 족보별 빈도가 알려진 값과 정확히 일치합니다. 벡터화 기준 초당 약 1,300만 핸드입니다.
- **프리플랍 1:1**: 보드 2,598,960개 × 핸드 1,081개 × 상대 핸드 990개를 모두 센 값입니다. 72o는 승 665,146,081 / 무 120,541,920 (콤보당 2,097,572,400가지 중)으로 독립 계산과 정수 단위까지 일치합니다. AA는 승 84.9319% / 무 0.5436% / 패 14.5245%입니다.
- **프리플랍 다인전**: 칸당 400만 회, 표준오차 최대 0.025%p (95% 구간 ±0.05%p). 이전 100만 회 테이블과는 최대 0.13%p 차이가 났습니다.
- **포스트플랍**: 전수 계산과 몬테카를로가 표준오차 0.5배 이내로 일치합니다. 가중치 레인지 전수 계산은 구성 레인지별 계산의 가중평균과 일치합니다.
- **계산 시간**: 6인 프리플랍 10만 회 약 0.1초. ±0.1%p 정밀도(6인) 약 1초. 핸드 대 핸드 프리플랍 전수 계산 약 0.5초. 플랍 1:1 전수 계산(1,070,190가지) 약 0.07초. 플랍에서 다음 카드 47장 각각의 전수 계산 약 0.1초.
- **엔진과 데이터 파이프라인**: 콜링 스테이션만 앉힌 160만 핸드에서 스타팅 핸드 169종 × 인원 2~9명 = 1,352칸의 실측 팟 점유율이 이론 승률과 통계적으로 일치했습니다(2σ 이내 94.9%, 3σ 이내 99.7%).

## 레인지 추정 모델의 효과

모델은 "어떤 상황에서 어떤 강도의 핸드로 어떤 액션을 했는가"를 센 표입니다. 상대의 액션을 관찰할 때마다 베이즈 규칙으로 1,326개 콤보의 가중치를 갱신합니다.

- **상황**: 스트리트, 그 스트리트에서 이미 나온 레이즈 수, 콜할 금액의 유무, 남은 인원, 테이블 크기(1:1 / 3~6인 / 7인 이상), 포지션.
- **포지션**: 프리플랍은 좌석(얼리, 미들, 컷오프, 버튼, 스몰 블라인드, 빅 블라인드), 플랍 이후는 남은 플레이어 중 행동 순서(처음, 중간, 마지막).
- **핸드 강도**: 그 보드에서 가능한 모든 핸드 중 상위 몇 %인지를 10구간으로 나눈 값.
- **드문 상황**: 상황은 굵은 것에서 세밀한 것으로 포개져 있고, 각 단계는 자기 데이터에 윗단계 확률 20회분을 더해 추정합니다. 몇 번 못 본 좌석은 그 테이블의 평균에 기대게 됩니다.

아래는 봇 자가대전으로 학습한 `selfplay` 모델입니다(`tag`/`lag`/`nit` 2~9인 대전 15,000핸드). 학습에 쓰지 않은 대전(다른 시드)에서 결정 시점 4,000개를 뽑아, 상대가 실제로 들고 있던 핸드 기준의 승률과 비교했습니다.

## 공개 핸드 히스토리로 학습한 모델

사람의 플레이를 읽으려면 사람의 데이터로 배워야 합니다. [PHH 데이터셋](https://github.com/uoftcprg/phh-dataset)(MIT 라이선스)의 두 묶음으로 학습한 모델을 함께 넣었습니다. 분석 도구(`equity`, 웹 화면)는 `online`을 기본으로 쓰고, 봇과 매일 학습은 `selfplay`를 씁니다.

| 모델 | 데이터 | 홀카드 |
|---|---|---|
| `online` | 2009년 7월 6개 사이트의 실전 캐시게임 203,204핸드 (HandHQ, 25NL~1000NL, 2~10인) | 쇼다운에서 보여준 것만: 플레이어-핸드의 5.1% |
| `pro` | Pluribus와 프로 5명의 6인 게임 10,000핸드 (Brown & Sandholm 2019) | 전부 공개 |
| `selfplay` | 이 패키지의 봇 자가대전, 매일 학습으로 갱신 | 전부 공개 |

`online`에는 스테이크 구간 프로필(`nl25-50`, `nl100-200`, `nl400-600`, `nl1000`)이, `pro`에는 `pluribus`와 `pro` 프로필이 들어 있습니다.

### 숨은 카드를 다루는 방법

실전 기록에서는 폴드한 핸드를 볼 수 없습니다. 보여준 핸드만 세면 끝까지 간 핸드만 남아 모델이 틀어집니다. 그래서 EM을 씁니다. 현재 모델로 각 플레이어의 숨은 핸드가 무엇이었을지를 그 판의 모든 액션을 근거로 추정하고, 그 확률만큼 나눠 세고, 다시 추정하기를 반복합니다. 카드가 공개된 플레이어는 그대로 한 번씩 셉니다.

학습은 2단계입니다. 먼저 테이블 크기와 포지션을 뺀 굵은 상황으로 수렴시키고, 그 답에서 출발해 세밀한 상황을 학습합니다. 세밀한 상황을 백지에서 바로 학습하면 실전 데이터에서 강한 핸드와 약한 핸드의 구분이 흐린 모델이 나왔습니다. 가장 약한 10% 핸드의 오픈 레이즈 빈도가 6%였고, 2단계 학습에서는 1%입니다.

정답을 아는 자가대전 데이터로 절차를 확인했습니다. 6만 핸드에서 실전 기록과 같은 비율(플레이어-핸드의 5.2%)만 카드를 남기고 학습한 뒤, 새 핸드 2,500개로 평가했습니다.

| 학습 방법 | 전체 정보 모델과의 확률 차이 | 액션당 로그우도 | 승률 평균 오차 |
|---|---|---|---|
| 전체 정보로 학습 (기준) | 0 | −0.275 | 11.88%p |
| EM 2단계 (카드 5.2%만 공개) | 3.1% | −0.292 | 11.81%p |

봇은 핸드 강도에 따라 기계적으로 행동해서, 이 데이터에서는 백지에서 한 번에 학습해도 결과가 같았습니다(확률 차이 3.0%). 2단계가 차이를 만든 것은 실전 데이터입니다.

### 실전 데이터에서의 결과

학습에 쓰지 않은 파일의 실전 4만 핸드에서, 각 모델이 실제 액션을 얼마나 잘 설명하는지입니다. "공개 핸드 적중"은 쇼다운에서 공개된 9,812핸드에 대해, 그 플레이어의 액션으로 추정한 레인지가 실제 핸드에 준 확률이 균등 추측의 몇 배인지(기하평균)입니다.

| 모델 | 액션당 로그우도 | 공개 핸드 적중 |
|---|---|---|
| `selfplay` | −1.541 | 0.00배 |
| `pro` | −0.857 | 1.49배 |
| 공개된 핸드만 세기 | −6.046 | 1.34배 |
| `online` (EM 2단계) | −0.702 | 2.17배 |

`selfplay`의 0.00배는 봇이 절대 하지 않는 액션(약한 핸드의 레이즈 등)을 사람이 하기 때문입니다. 그런 핸드에 거의 0의 확률을 주면 기하평균이 0으로 떨어집니다.

승률 추정의 정확도는 모든 홀카드를 아는 Pluribus 데이터로 쟀습니다. 1만 핸드에서 결정 시점을 하나씩 뽑았고, `pro`는 5겹 교차검증(학습에 쓰지 않은 핸드로 평가)입니다.

| 상대 레인지 | 평균 절대 오차 | RMSE | 플랍 이후 편향 |
|---|---|---|---|
| 랜덤 핸드 가정 | 11.65%p | 18.47%p | +11.0%p |
| `selfplay` | 10.33%p | 17.69%p | +6.5%p |
| `online` | 10.23%p | 16.18%p | +3.2%p |
| `pro` (교차검증) | 10.17%p | 16.08%p | +1.3%p |

2009년 온라인 플레이어로 학습한 `online`이 프로 본인들의 데이터로 학습한 `pro`에 가깝습니다(같은 결정 시점에서 평균 오차 차이 0.06 ± 0.05%p). `selfplay`와의 평균 오차 차이는 0.10 ± 0.14%p로 유의하지 않지만, 큰 오차가 줄어 RMSE가 낮습니다. 70~80%라고 계산했을 때 실제 승률은 `selfplay` 57%, `online` 72%였습니다.

학습된 습관의 예입니다. 가장 약한 10% 핸드에서 가장 강한 10% 핸드 순서로, 둘만 남은 플랍에서 체크가 돌아왔을 때 벳하는 빈도입니다.

| 모델 | 최약 | | | | | | | | | 최강 |
|---|---|---|---|---|---|---|---|---|---|---|
| `online` | 18% | 19% | 21% | 27% | 33% | 43% | 41% | 47% | 55% | 64% |
| `pro` | 19% | 19% | 25% | 25% | 27% | 31% | 32% | 31% | 32% | 52% |
| `selfplay` | 10% | 9% | 9% | 9% | 11% | 22% | 54% | 85% | 99% | 100% |

봇은 강할 때만 벳하고, 사람은 약한 핸드로도 벳하며 강한 핸드로도 체크합니다. 봇으로 배운 모델이 사람의 액션을 잘못 읽는 이유입니다.

### 포지션과 테이블 크기의 효과

같은 액션이라도 좌석에 따라 뜻이 다릅니다. 앞이 모두 폴드했을 때 레이즈로 들어오는 빈도입니다.

| | 6인 미들 | 6인 컷오프 | 6인 버튼 | 6인 스몰 블라인드 | 9인 얼리 | 1:1 버튼 |
|---|---|---|---|---|---|---|
| `online` | 17% | 24% | 36% | 30% | 9% | 58% |
| `pro` | 20% | 29% | 43% | 32% | - | - |

분석 도구에서도 같은 "오픈 레이즈 후 플랍 벳"의 추정 레인지 폭이 좌석에 따라 달라집니다. 6인 테이블에서 좌석을 모르면 22%, 컷오프 33%, 버튼 45%, 9인 테이블 UTG는 15%, 1:1 테이블 버튼은 66%입니다.

이 두 가지를 넣기 전후를 같은 데이터로 비교했습니다.

| 측정 | 넣기 전 | 넣은 후 |
|---|---|---|
| `online`: 실전 보류 4만 핸드 액션당 로그우도 | −0.721 | −0.702 |
| `online`: 실전 보류 공개 핸드 적중 | 2.12배 | 2.17배 |
| `pro`: Pluribus 교차검증 액션당 로그우도 | −0.459 | −0.444 |
| `human` 봇의 1:1 VPIP / PFR (실제 53.0% / 35.5%) | 38.8% / 25.0% | 52.8% / 35.1% |
| `human` 봇의 9인 VPIP / PFR (실제 21.4% / 9.3%) | 23.2% / 11.8% | 20.9% / 9.0% |
| `online`: Pluribus 승률 평균 오차 | 10.17%p | 10.23%p |
| `pro`: Pluribus 승률 평균 오차 (교차검증) | 10.17%p | 10.17%p |
| `selfplay`: 보류 자가대전 승률 평균 오차 | 11.3%p | 11.4%p |
| `pro` 모델을 실전 온라인 데이터에 적용한 공개 핸드 적중 | 1.88배 | 1.49배 |

액션을 설명하는 능력은 좋아졌고, 개선의 대부분은 포지션에서 나왔습니다(테이블 크기만 넣으면 로그우도 −0.718). 테이블 크기별 습관도 재현됩니다. 반면 승률 추정 오차는 Pluribus 데이터에서 달라지지 않았습니다. 그리고 모델이 세밀해진 만큼 집단 고유의 습관을 더 담게 되어, 한 집단의 모델을 다른 집단에 적용했을 때는 오히려 나빠진 경우가 있습니다(마지막 행).

### 사람처럼 치는 봇

`human`과 `pro` 봇은 각 상황에서 자기 핸드 강도 구간의 폴드·콜·레이즈 빈도를 모델에서 찾아 그 비율대로 행동합니다. 모델이 데이터를 제대로 담았다면 이 봇의 통계가 원본 데이터와 같아야 합니다.

| | 봇끼리 대전 VPIP / PFR | 원본 데이터 VPIP / PFR |
|---|---|---|
| `human`, 1:1 | 52.8% / 35.1% | 53.0% / 35.5% (1:1 테이블) |
| `human`, 6인 | 26.5% / 14.8% | 28.0% / 16.2% (3~6인 테이블) |
| `human`, 9인 | 20.9% / 9.0% | 21.4% / 9.3% (7~10인 테이블) |
| `pro`, 6인 | 26.6% / 17.7% | 26.3% / 17.6% |

원본의 3~6인 묶음에는 3~5인 테이블도 들어 있어, 6인만 앉힌 봇 테이블보다 조금 느슨한 것이 맞습니다.

이 봇 3명이 앉은 6인 테이블(6만 핸드)에서 에퀴티 봇의 성적은 `tag`(레인지를 읽지 않음) −51 ± 12, `tag_model` +28 ± 8, `online` 모델로 읽는 봇 +29 ± 8 bb/100이었습니다. 레인지를 읽으면 손실이 수익으로 바뀌지만, 어느 모델로 읽는지는 이 대전에서 차이가 없었습니다. 1:1에서는 `tag`가 `human`과 비겼고(+6 ± 23), `online` 모델로 읽는 봇은 +59 ± 15였습니다.

### 모델을 쓰는 봇의 성적

`tag_model`은 `tag`와 베팅 규칙이 같고, 승률을 랜덤 핸드 가정 대신 추정 레인지 기준으로 계산한다는 점만 다릅니다. 각 3만 핸드 결과입니다.

| 대전 | `tag_model`의 bb/100 (95% 신뢰구간) |
|---|---|
| 1:1, 상대 `tag` (랜덤 핸드 가정) | +341 ± 24 |
| 1:1, 상대 `tag_range` (레이즈한 상대를 상위 20%로 가정) | +99 ± 16 |
| 6인 (`tag`, `tag_range`, `nit`, `lag` 2명과 함께) | +127 ± 17 |

6인 리그의 나머지 봇은 `tag_range` +67, `nit` +41, `tag` −10, `lag` −113 bb/100이었습니다.

| 봇 구성 (6인, 액션 로그 포함) | 1코어 | 4코어 |
|---|---|---|
| 에퀴티 기반 봇 (`tag`, `lag`, `nit`) | 1,230 핸드/초 | 4,544 핸드/초 |
| 계산 없는 봇 (`station`, `random`, `maniac`) | 6,414 핸드/초 | 14,469 핸드/초 |

저장 용량은 액션 로그 포함 시 핸드당 약 0.8~1.0KB입니다. 혼합 리그(6인, 40만 핸드)에서는 `lag` +1,146, `tag` +601, `nit` +330, `maniac` −646, `station` −699, `random` −731 bb/100이었고, 에퀴티 봇끼리만 붙이면 `nit` +53, `tag` +29, `lag` −82 bb/100으로 격차가 10분의 1 이하로 줄었습니다.

## 한계

- `online` 모델은 2009년 온라인 캐시게임, `pro` 모델은 한 번의 실험에 참가한 프로들의 플레이입니다. 지금의 게임이나 특정 상대의 습관과는 다를 수 있습니다.
- 챔피언과 `selfplay` 모델은 이 봇 풀의 플레이에서 배운 것이라 사람 상대 수익률로 읽으면 안 됩니다.
- 레인지 모델은 베팅 크기와 스택 깊이를 보지 않습니다. 상황 구분도 거칩니다(레이즈 수 0/1/2+, 남은 인원 2/3/4/5+, 테이블 크기 3단계).
- 액션을 직접 입력할 때는 그때 누가 폴드해 있었는지를 모르므로 가정이 들어갑니다(프리플랍은 앞이 모두 폴드, 플랍 이후는 지금 남은 인원 그대로). 림프가 여럿 있던 판 같은 경우에는 맞지 않습니다.
- 봇은 단순한 규칙 기반이며 균형 전략(GTO)이 아닙니다.
- 매 핸드 스택을 100bb로 초기화하고 좌석을 섞습니다. 레이크·앤티·토너먼트 구조는 없습니다.
- 승률은 "지금 올인해서 끝까지 갔을 때"의 값입니다. 이후 베팅 라운드와 포지션의 영향은 반영하지 않습니다.
- 전수 계산은 핸드가 모두 정해진 경우, 포스트플랍 상대 1명, 턴·리버 상대 2명(레인지 없음)까지입니다. 나머지는 몬테카를로입니다.
