# 돌발상황 대응 매뉴얼

게임이나 프로그램이 예상과 다르게 움직일 때 pokerlab이 무엇을 보고 알아채는지, 스스로 어떻게 대응하는지, 사람이 할 일은 무엇인지 정리했습니다. 1부는 pokerlab으로 창을 읽는 동안, 2부는 자동 플레이와 영상 녹화 도구(`tools/demo/record.py`)입니다.

새 돌발상황을 만나면 이 문서의 표에 한 줄을 더하고, 자동으로 처리할 수 있으면 코드에도 넣습니다(2부 끝의 '새 돌발상황을 만났을 때').

## 1부. 창을 읽는 동안

상태 줄은 소스 아래에 나오는 한 줄 설명입니다. 표의 문구는 화면에 그대로 나오는 문구입니다.

| 상황 | 알아채는 방법 | pokerlab이 하는 일 | 사람이 할 일 |
|---|---|---|---|
| 프로그램의 팝업, 팁, 메뉴가 테이블을 가림 | 상태 줄 맨 앞에 "화면이 가려져 있어 읽은 값을 쓰지 않았습니다 (n장째)", 뒤에 "가려져서 쓰지 않은 화면 n장" | 인식 단계가 가려진 화면이라고 답하면 그 화면은 핸드에 넣지 않음. 같은 화면이 이어지면 읽는 간격을 늘림 | 팝업을 닫습니다. 그 프로그램에 팁 끄기 설정이 있으면 꺼 둡니다 |
| 화면은 계속 움직이는데 테이블은 그대로 (애니메이션, 타이머 막대) | 상태 줄 끝에 "같은 테이블이 계속 읽혀 n초마다 읽습니다" | 같은 테이블을 3번 연달아 읽으면 간격을 2배씩 늘려 최대 30초. 화면의 3% 이상이 바뀌면(카드, 칩, 창이 닫힘) 기다리지 않고 바로 읽음 | 없음. 그래도 비용이 많으면 소스의 다시 읽는 최소 간격을 늘립니다 |
| 핸드와 핸드 사이 (카드를 거두고 나누는 중) | "다음 핸드를 기다리는 중". 8장 넘게 이어지면 "화면을 계속 읽지 못합니다 (n장째)"와 이유 | 오류로 보지 않고 기다림 | 8장 넘게 이어지면 이유를 보고, 고른 창이 맞는지와 소스 메모를 확인합니다 |
| 창을 닫거나 공유를 멈춤 | "창 공유가 끝났습니다" | 그 소스는 더 읽지 않음 (비용 없음) | "창 추가"로 다시 고릅니다 |
| 앞선 화면과 이어지지 않는 화면 (숫자 오독 등) | 표 아래 메모 "앞선 화면과 이어지지 않아 지금 화면부터 다시 읽었습니다", 상태 줄 "다시 읽음 n번" | 내 차례가 아니면 다음 화면을 기다려, 다음 화면이 그 화면 없이 이어지면 한 장짜리 오독으로 버림. 아니면 그 화면부터 다시 따라감 (그 핸드는 학습에서 뺌) | 표의 값이 틀려 보이면 "핸드 다시"를 누릅니다. 자주 나오면 소스 메모를 보강합니다 |
| 내 자리를 다른 자리로 읽음 (딜러 인물, 카드를 연 상대) | 상태 줄 "내 자리를 다른 곳으로 읽은 화면 n/m", 10%를 넘으면 메모 안내 | 소스마다 내 카드가 보인 자리를 기억해 그 자리로 바로잡음 | 소스 메모에 내 자리를 적습니다 (예: 내 자리는 위 가운데) |
| 칩 합계가 안 맞음 (스택이나 팟 오독) | 상태 줄 "칩 합계가 안 맞은 화면 n/m" | 핸드 전체를 보고 한 장짜리 오독을 바로잡음 | 잦으면 소스 메모에 금액 단위나 누적 금액 표시인지를 적습니다 |
| 보드나 내 카드가 화면마다 다르게 읽힘 | 상태 줄 "보드만 크게 다시 읽음 n번", "내 카드만 다시 읽음 n번" | 자리마다 다수결. 새 스트리트마다 보드를 잘라 키운 그림으로 다시 읽고, 내 카드는 읽기가 갈리면 다시 읽음 (응답 뒤에 따로, 한 번에 약 0.01달러) | 없음 |
| 읽기가 느림 | 상태 줄 "평균 n초" | 없음 | 읽는 방식을 "빠르게"로 바꿉니다 (약 2.2초, 비용 2배) |
| 비용이 예상보다 큼 | 상태 줄 "약 $n" | 위의 간격 늘리기 | 다시 읽는 최소 간격을 늘리거나, 스택이 숫자로 보이는 프로그램이면 "아껴서"로 바꾸거나, 쓰지 않는 소스를 지웁니다 |
| API 키가 없거나 거부됨 | 오류 "Claude API 키가 없거나 거부됐습니다" | 그 화면을 읽지 못함 | `python -m pokerlab check`로 키가 어느 환경 변수에 있는지 확인하고 다시 넣습니다 |
| 사용량 한도에 걸림 | 오류 "Claude API 사용량 한도에 걸렸습니다" | 그 화면은 건너뛰고, 화면이 바뀌면 다시 시도 | 소스 수를 줄이거나 간격을 늘립니다 |
| 빠른 모드의 한도에 걸림 | 없음 | 그 장은 바로 보통 속도로 읽음 | 없음 |
| Claude가 화면 읽기를 거절함 | 오류 "Claude가 이 화면을 읽지 않겠다고 했습니다" | Opus 5.5와 Sonnet 5.5는 같은 호출 안에서 다른 모델이 이어 읽음. 그래도 거절되면 다음 화면에서 다시 | 반복되면 그 화면에 테이블 말고 다른 것이 크게 보이는지 확인합니다 |
| pokerlab 서버가 꺼짐 | "서버에 연결할 수 없습니다" | 없음 | `python -m pokerlab serve --record hands.jsonl`을 다시 실행합니다 |

가려진 화면 알아채기는 실제 읽기로 쟀습니다. 정상 화면 25장(Flash 12, HTML5 13)은 하나도 가려졌다고 하지 않았고, 가려진 화면 10장(Flash 게임의 Tip 창 6장, HTML5 게임의 상대 수 고르기 창 1장, 테이블 위에 그린 광고 창 3장)은 모두 알아챘습니다(약 0.63달러).

새 프로그램을 쓰기 전에 하면 좋은 것:
- `python -m pokerlab check`로 키와 인식을 확인합니다.
- 프로그램의 팁, 튜토리얼, 광고 창을 끌 수 있으면 끕니다.
- 소스 메모에 내 자리, 딜러 인물, 금액 표시 방식처럼 화면에서 확실한 것만 적습니다.
- 처음 몇 핸드는 표의 값과 상태 줄의 품질 표시를 함께 봅니다.

## 2부. 자동 플레이와 영상 녹화

`record.py`는 게임을 직접 플레이하므로, 게임이 멈추면 아무도 버튼을 누르지 않습니다. 2026-11-19 이전의 Flash 세로 영상에서는 게임이 "Tip: Raise button" 창을 띄우고 Close를 기다리는 동안, 플레이어가 CALL 자리만 계속 눌러 약 1분 45초 동안 멈춰 있었고 pokerlab은 가려진 화면을 계속 읽었습니다. 지금은 감시 장치(`tools/demo/watchdog.py`)가 이렇게 합니다.

1. **알아채기**: 게임 화면(약 0.7초마다 저장)을 160x100으로 줄여, 15초 동안 화면의 3% 이상이 바뀐 순간이 한 번도 없으면 멈춘 것으로 봅니다. 그 영상에서 Tip 창의 작은 움직임은 1.2% 아래였고, 실제 플레이는 20초 안에 늘 7% 이상 바뀌었습니다.
2. **대응** (싼 것부터, 한 단계마다 3초 뒤 다시 확인):
   1. 그 게임에 알려진 처리 (`record.py`의 `GAMES`)
   2. Esc 키, Enter 키
   3. Claude에게 화면을 보여 주고 무엇이 막고 있는지, 어디를 눌러야 하는지 물어 그대로 함 (한 번 약 0.01달러). 사기, 결제, 공유, 로그인, 게임 나가기 버튼은 고르지 말라고 지시합니다. 막은 것이 없다고 하면 기다립니다.
3. **포기**: 이 순서를 두 번 돌아도 게임이 움직이지 않으면 플레이와 읽기를 멈춥니다(비용을 막기 위해). 그때까지 찍은 것으로 영상을 만듭니다.
4. **기록**: 모든 돌발상황을 `OUT/incidents.json`에 남깁니다(시각, 멈춘 시간, 해 본 것과 결과, Claude의 판단, 그때 화면 `incident_N.jpg`). 끝날 때 요약을 출력합니다.

| 상황 | 대응 | 확인한 결과 |
|---|---|---|
| Flash 게임의 Tip 창 (상대가 딜러 버튼에서 레이즈하면 한 번 뜸) | 알려진 처리: "Hide all tips"를 누르고 Close. 안 되면 Claude | 저장된 Tip 화면에서 Claude가 "Tip 창, Close와 Hide all tips"로 알아보고 그 자리를 골랐음. 14분 시험 플레이에서는 이 창이 다시 뜨지 않음 |
| 메뉴 클릭이 빗나가 메인 메뉴나 게임 설정 화면에 머묾 | Claude가 고른 곳 클릭 | 실제로 일어남: Claude가 메인 메뉴에서 Quick Poker, 설정 화면에서 Play를 차례로 눌러 게임이 다시 시작됨 |
| 쇼다운 화면이 15초 넘게 그대로 | Claude가 막은 것 없음으로 보고 기다림 | 실제로 일어남 (0.009달러) |
| HTML5 게임이 끝남 ("GAME OVER" 메시지, "Start a new game" 버튼, 상대 수 고르기) | 알려진 처리: 메시지 OK, "Start a new game"(이때는 폴드 버튼 자리), 상대 5명, 가장 느린 속도 | 상대 칩을 0으로 만들어 끝내 본 시험에서 Claude 없이 알려진 처리만으로 다시 시작됨 |
| 브라우저의 알림 창 (alert, confirm) | 드라이버가 바로 닫고 내용을 돌발상황으로 기록 | 시험 중에는 뜨지 않음 |
| 브라우저가 시작하자마자 끝남 | 드라이버가 답할 때까지 최대 60초 기다리고, 끝나 버리면 이유와 확인할 것을 출력하고 멈춤 | 실제로 일어남: 새 Chromium이 그래픽 옵션 `--use-gl=swiftshader`를 거부해 바로 꺼졌고, `--use-angle=swiftshader`로 바꿈 |
| 읽기 비용이 정한 예산에 닿음 | `--budget 달러`를 주면 플레이와 읽기를 멈추고 기록 | 단위 시험 |
| 무엇을 해도 게임이 움직이지 않음 | 플레이와 읽기를 멈추고 incidents.json에 "해결 못함" | 단위 시험 |

시험 방법:
- `--no-read`: pokerlab 없이 플레이와 감시만 합니다(비용 없음, Claude에게 묻는 경우만 한 번 약 0.01달러).
- `--no-ask`: Claude에게 묻지 않고 알려진 처리와 키만 씁니다.

```bash
python pokerlab/tools/demo/record.py flash GAME_DIR out_flash --minutes 6 --no-read
```

### 새 돌발상황을 만났을 때

1. `OUT/incidents.json`과 `incident_N.jpg`를 봅니다. Claude가 무엇으로 보았고 무엇을 눌렀는지가 남아 있습니다.
2. 자주 나오는 것이면 `record.py`에 그 게임의 알려진 처리를 함수 하나로 더하고 `GAMES`의 목록에 이름을 넣습니다. 알려진 처리가 먼저 시도되므로 Claude에게 묻는 비용이 들지 않습니다.
3. pokerlab이 읽는 쪽의 문제(가려진 화면을 테이블로 읽음 등)이면 1부의 표와 코드를 함께 고칩니다.
4. 이 문서의 표에 한 줄을 더합니다.
